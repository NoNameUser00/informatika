## Паттерн 1. Дизайн interactive-сцен (deep-interactive)

- По умолчанию «делать», не читать: `slide` — только рамка вопроса и итоговая консолидация.
- Одна сцена = один механизм/переменная/структура. Подряд один `widgetType` — брак; модальность варьировать: смотреть → проследить → предсказать.
- Заголовки называют действие/открытие («Двигай делитель — смотри остатки»), не тему («Перевод чисел»).
- `keyPoints` сцены = что меняешь → что наблюдаешь → какой вывод следует. Не список фактов.
- Типы виджетов: `simulation` (крути параметры, смотри отклик), `diagram` (раскрывай структуру),
  `code` (читай/меняй/запускай короткую программу), `game` (повторяющиеся решения по правилам, счёт движется).

## Паттерн 2. Арка урока (k12, 6–10 страниц на 45 мин)

1. `slide`: ситуация, открытый вопрос, итоговое задание.
2. `interactive`: наблюдение/манипуляция, сбор улик.
3. `interactive`/`slide`: сравнение, классификация, модель.
4. `quiz`: диагностика главного заблуждения + требование обоснования (дистракторы — из реальных ошибок, фидбек учит, а не ставит «неверно»).
5. `interactive`/задание: ученик производит объяснение/модель/решение.
6. `slide`: критерии успеха, опора, фрагмент-образец.
7. `quiz`/задание: перенос в новый контекст.
8. `slide`: консолидация метода.

Наши дистракторы в банке (из `common_errors` скилла numsys-tutor) этому уже соответствуют — держать планку.

## Паттерн 3. Реализация (InteractiveIframeHost)

- Сим — самодостаточный HTML в `<iframe sandbox="allow-scripts" srcDoc={...}>`, БЕЗ `allow-same-origin`
  (null-origin; связь с родителем только через `postMessage`). Это ровно наше правило «код — только в песочнице».
- Плюс: баннер ошибок рантайма, наблюдаемость (observation identity), перерендер при смене сцены.
- Для Astro: React-острова `.tsx`, рендерящие такие iframe; HTML без внешних запросов (работает с GitHub Pages офлайн).
  Прогресс — позже через Supabase, сейчас локально.
- Доступность (AGENTS.md): все контролы с labels, клавиатурная работа, контраст WCAG AA.

## Маппинг на 6 эпизодов «Систем счисления»

| Эпизод | Виджет | Сим: меняешь → наблюдаешь → вывод |
|---|---|---|
| 1. Позиционные/непозиционные | `diagram` | Раскрывай узлы: разряды 8-4-2-1 vs знаки X/V/I; вывод: значение зависит/не зависит от позиции |
| 2. Перевод 10→2/8/16 | `simulation` | Слайдер числа 0–255 + выбор основания; столбик делений и сборка остатков снизу вверх |
| 3. Перевод 2/8/16→10 | `code` | Читай/меняй/запускай 10-строчный конвертер развёрнутой формой; предскажи результат до запуска |
| 4. Тетрады/триады | `diagram` | Кликай биты в группы по 4/3, группы подсвечиваются hex/oct цифрами; вывод: длина записи ~ log |
| 5. Арифметика в двоичной | `game` | Складывай столбиком по битам с переносом, счёт за верные переносы; ошибка показывает перенос |
| 6. Цепочки и единицы | `simulation` + `game` | Трейсер цепочки 16→2→подсчёт; matching-игра пар «10↔1010₂» на время |

## Карта применения по темам (2026-10-06)

### 1. dnd-kit matching — готов, работает везде сам
- Что: перетаскивание соответствий (мышь/тач/клавиатура + tap). Уже унифицировано: любое задание `type: matching` в любом банке автоматически с DnD.
- Где применять: 8-СС (009/053/054 — записи чисел), 8-логика (008 — операции/знаки), дальше — везде, где пара «термин — значение»: 7-информация (понятия), 9-моделирование (типы моделей), 11-БД (типы полей), 11-сети (топологии).
- Шаги: методист пишет matching-задания в `bank.yaml` — ничего кодить не надо.

### 2. Pyodide-раннер — готов v1, ждёт тип заданий
- Что: код ученика выполняется в браузере (песочница=WASM), вывод сверяется с эталоном. Только тренажёр/практика, не контрольная.
- Где применять:
  - 8-СС уже сейчас: `print(bin(13))`, `hex(175)`, `int('101101', 2)` — самопроверка переводов кодом;
  - 8-Python (гл.5) и 9-алгоритмы: первые программы, циклы (таблица переводов циклом!), Евклид, сортировки;
  - 10–11: обработка данных (через micropip доступны numpy/matplotlib).
- Шаги: спроектировать тип `code_run` в банке (`student_view.code`, `expected_stdout`) → добавить в `schema.ts` + Trainer (рендер через PyRunner, проверка `compareOutput`) → воркер с interrupt до продакшена.
- Честно: Pascal (8-гл.4) не покрыт — для него нужен другой раннер/серверная песочница.

### 3. Доска Excalidraw — готова (2026-10-06)
