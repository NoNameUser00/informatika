## 5. inf-11-db-010

**Вопрос.** Нужно узнать, сколько записей у каждого класса. Какое ключевое слово группирует строки так, чтобы для каждой группы можно было применить COUNT или SUM?

* **B.** GROUP BY — группирует строки по значениям поля, чтобы посчитать для каждой группы
* **A.** ORDER BY — группирует строки по значениям поля ← сейчас ключ
* **D.** FROM — группирует строки по значениям поля
* **C.** WHERE — группирует строки по значениям поля

**Ключ сейчас: A** — ORDER BY — группирует строки по значениям поля

**Почему так.** GROUP BY собирает строки с одинаковым значением поля в группу, после чего COUNT или SUM считают по каждой группе отдельно. ORDER BY только меняет порядок строк, а WHERE и вовсе ничего не группирует.

Урок: `11db-02-queries` · basic · 1 балл.

## 6. inf-11-db-014

**Вопрос.** В школе каждый ученик состоит ровно в одном классе, а в классе учатся несколько учеников. Какой тип связи описывает таблица «Ученики» со справочником «Классы»?

* **D.** Связи нет: две таблицы просто стоят рядом и никак не зависят друг от друга ← сейчас ключ
* **C.** Один к одному: каждому ученику соответствует ровно один класс, и наоборот
* **B.** Многие ко многим: ученик может состоять сразу в нескольких классах, а класс — включать много учеников
* **A.** Один ко многим: каждому ученику соответствует ровно один класс, а в классе может быть много учеников

**Ключ сейчас: D** — Связи нет: две таблицы просто стоят рядом и никак не зависят друг от друга

**Почему так.** Это связь «один ко многим»: со стороны ученика поле «код класса» хранит ссылку на одну строку справочника, а на один класс ссылаются многие строки таблицы учеников. Такой столбец называется внешним ключом. Связь «многие ко многим» потребовала бы отдельной таблицы-перекрёстка, а «один к одному» здесь просто противоречит жизни.

Урок: `11db-01-databases` · basic · 1 балл.

## 7. inf-11-db-018

**Вопрос.** Блюдо «Борщ» заказывали четыре раза, и в результате запроса его название встретилось четыре раза подряд. Какое ключевое слово оставит в результате только одно название?

* **C.** GROUP BY: оставляет в результате только различные значения выбранного поля
* **D.** COUNT: оставляет в результате только различные значения выбранного поля ← сейчас ключ
* **B.** ORDER BY: оставляет в результате только различные значения выбранного поля
* **A.** DISTINCT: оставляет в результате только различные значения выбранного поля

**Ключ сейчас: D** — COUNT: оставляет в результате только различные значения выбранного поля

**Почему так.** DISTINCT убирает одинаковые значения выбранного поля: SELECT DISTINCT название FROM Поставки вернёт «Борщ» один раз. ORDER BY только меняет порядок строк, GROUP BY собирает строки в группы для подсчёта, а COUNT считает их количество — ни одно из этих слов повторы в результате не удаляет.

## 8. inf-11-db-019

**Вопрос.** Нужно вывести записи о работах так, чтобы они шли от самой высокой оценки к самой низкой. Как закончится запрос?

* **B.** ORDER BY балл ASC
* **D.** WHERE балл DESC
* **A.** ORDER BY балл DESC
* **C.** GROUP BY балл DESC ← сейчас ключ

**Ключ сейчас: C** — GROUP BY балл DESC

**Почему так.** ORDER BY задаёт порядок строк результата, а DESC означает «по убыванию». По умолчанию сортировка и так идёт по возрастанию, поэтому ASC можно не писать, но для читаемости его часто оставляют. GROUP BY не сортирует строки, а объединяет одинаковые значения в группы, а DESC в WHERE не существует вовсе.

Урок: `11db-02-queries` · basic · 1 балл.
