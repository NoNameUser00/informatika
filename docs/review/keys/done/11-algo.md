## 12. inf-11-algo-045

**Вопрос.** Программа ищет наибольший элемент списка из 5 чисел так: for i in range(len(a)): если a[i + 1] > best, best = a[i + 1]. Что произойдёт?

* **D.** Программа зациклится и будет обращаться к a[5], a[6], a[7] и дальше
* **C.** Программа выведет 0: несуществующий элемент считается нулём
* **B.** Программа выведет правильный максимум: лишний шаг цикла ничего не меняет
* **A.** Программа завершится с ошибкой: при i = 4 обращение к a[5] выходит за границу списка ← сейчас ключ

**Ключ сейчас: A** — Программа завершится с ошибкой: при i = 4 обращение к a[5] выходит за границу списка

**Почему так.** Обращение идёт к элементу с индексом i + 1, а цикл доходит до i = 4. Тогда программа просит a[5], а такого элемента нет — Python сообщает IndexError. Классическая ошибка на единицу: либо цикл строят от 0 до n − 2, либо последний элемент обрабатывают отдельно.

Урок: `11algo-02-debug` · basic · 1 балл.

Вердикт: верно

## 13. inf-11-algo-052

**Вопрос.** Чем отличается сортировка подсчётом от остальных способов сортировки?

* **C.** Сортирует только числа, а строки оставляет в исходном порядке
* **D.** Удаляет из списка повторяющиеся элементы
* **B.** Считает число сравнений и печатает его в конце работы
* **A.** Выстраивает элементы по количеству их значений, не сравнивая элементы попарно ← сейчас ключ

**Ключ сейчас: A** — Выстраивает элементы по количеству их значений, не сравнивая элементы попарно

**Почему так.** Сортировка подсчётом сначала подсчитывает, сколько раз встречается каждое значение, а затем выкладывает элементы по этим частотам. Сравнения элементов между собой при этом не нужны совсем, поэтому она работает за O(n + k), где k — число различных значений. Побочная сторона: значения должны быть небольшими целыми числами.

Урок: `11algo-06-sorting` · basic · 1 балл.

Вердикт: верно

## 14. inf-11-algo-065

**Вопрос.** Какая сложность у двоичного (бинарного) поиска в отсортированном массиве?

* **B.** O(n): просматриваются все элементы подряд
* **C.** O(n²): проверяются все пары элементов
* **D.** O(1): поиск занимает ровно одно действие
* **A.** O(log n): на каждом шаге отбрасывается половина диапазона ← сейчас ключ

**Ключ сейчас: A** — O(log n): на каждом шаге отбрасывается половина диапазона

**Почему так.** Двоичный поиск сравнивает элемент с серединой диапазона и отбрасывает половину: 1000 элементов превращаются в 500, 250 и так далее. Диапазон падает вдвое на каждом шаге, поэтому время растёт как O(log n). Линейный поиск, который просматривает элементы подряд, требует O(n) сравнений.

Урок: `11algo-11-complexity` · basic · 1 балл.

Вердикт: верно
