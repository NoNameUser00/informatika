## 1. RAG-бэкенд `backend/` (llama-index + Qdrant, Python 3.12)

### Окружение (восстановить одной командой)
```sh
uv venv --python 3.12 backend/.venv
uv pip install --python backend/.venv/Scripts/python.exe -r backend/requirements.txt
```
Состав: `llama-index-core>=0.14`, `readers-file`, `embeddings-huggingface`, `llms-ollama`,
`vector-stores-qdrant>=0.9`, `qdrant-client`, `pyyaml`, `pydantic`, `pytest`, `fonttools`.
Внимание: qdrant-интеграция требует Python <3.14 — только `.venv`, не системный 3.14.

### Env (всё опционально, только окружение; пример — `backend/.env.example`)
`OLLAMA_HOST`, `LLM_MODEL=llama3.1`, `EMBED_MODEL_NAME` (мультиязычный MiniLM),
`INDEX_PERSIST_DIR`, `VECTOR_STORE=file|qdrant`, `QDRANT_URL` (пусто = локальный файл),
`QDRANT_API_KEY`, `QDRANT_PATH`, `QDRANT_COLLECTION`, `OPENROUTER_API_KEY/MODEL/BASE_URL`,
`BANK_PATH`, `DOC_PATHS`.

### Команды
```sh
backend/.venv/Scripts/python.exe backend/scripts/build_index.py [--embed hf|mock] [--store file|qdrant]
backend/.venv/Scripts/python.exe backend/scripts/query_demo.py --query "..." [--store qdrant] [--with-llm]
backend/.venv/Scripts/python.exe backend/tests/test_corpus.py
backend/.venv/Scripts/python.exe backend/tests/test_qdrant_store.py
backend/.venv/Scripts/python.exe backend/tests/test_openrouter.py
```
`--embed mock` — без скачивания моделей. `query_demo --with-llm` требует запущенную Ollama.

### Модули (`backend/src/rag_informatics/`)
- `corpus.py` — корпус ТОЛЬКО из `student_view` (allowlist + `assert_no_teacher_markers`). Новым темам — сюда не лезть, формат общий.
- `indexing.py` — `build_index/load_index(..., embed_kind, store_kind)`; `qdrant_store.py` — local-режим без сервера / server через `QDRANT_URL`.
- `query.py` — `QueryRequest` (pydantic), `retrieve()` (без LLM), `answer()` (Ollama), `SYSTEM_PROMPT` (подсказки, не готовые ответы).
- `openrouter.py` — `chat()` на stdlib + `answer_openrouter()` (retrieve + генерация). Ключ строго из env.
- `backend/docker-compose.yml` — self-host Qdrant (когда будет docker).

### Тесты корпуса — устойчивы к росту банка
Проверяют: число загруженных = числу в YAML (сейчас 13), отсутствие teacher-маркеров и всех `explanation`
в индексе, валидацию запросов. Новый банк проверяй теми же тестами (поменяй путь — сейчас захардкожен дефолт).

## 3. Интерактив сайта (готово, покрыто тестами и E2E)

- **Matching-DnD** (`src/components/DragMatch.tsx`, dnd-kit 6.3.1): любое задание `type: matching` в любом банке
  автоматически с перетаскиванием (мышь/тач/клавиатура + tap, RU-анонсы). Trainer и Slides унифицированы.
  Чистая логика: `src/lib/matching/drop.mjs` (+16 тестов в `npm test`).
- **PyRunner** (`src/components/PyRunner.tsx`): Python в браузере (Pyodide 0.27.0 с CDN, MPL-2.0),
  вывод + сверка с эталоном (`src/lib/pyrun/compare.mjs`, 8 тестов). Только тренажёр, не контрольная.
  Ограничение: главный поток — до продакшена нужен воркер с interrupt.
- **BlocklyRunner** (`src/components/BlocklyRunner.tsx`): блоки (Blockly 13.3.0, Apache-2.0, RU) → Python → Pyodide.
  Общий загрузчик: `src/lib/pyrun/pyodide.ts`.
- Следующий виджет по плану: **доска Excalidraw** (MIT) — блок-схемы, топологии, ER-схемы. Пока не начата.
- Карта применения по темам + статусы: `docs/interactive-sims.md` (там же паттерны OpenMAIC и лицензии PhET:
  библиотеки MIT — можно, код симов GPL-3.0 — нельзя).
- Следующий тип банка под раннеры: спроектировать `code_run` (`student_view.code` + `expected_stdout`) → `schema.ts` + Trainer.
