# Объект как таблица

**Табличная модель** — описание объекта в виде таблицы: столбцы — **поля** (свойства), строки — **записи** (экземпляры).

Однотабличная база «Ученики»:

| Фамилия | Класс | Рост | Возраст |
|---|---|---|---|
| Иванов | 9А | 170 | 15 |
| Петрова | 9А | 165 | 15 |
| Сидоров | 9Б | 178 | 14 |

Каждая строка — один ученик. Каждый столбец — одно свойство всех учеников.

## Требования к таблице

1. **Все значения в столбце — одного типа.** Рост — числа, Фамилия — текст. Смешивать нельзя.
2. **Шапка** — названия столбцов.
3. **Каждая строка — один объект.** Не записывай в одну ячейку «Иванов, 170 см».
4. **Пропуск — прочерк**, а не пустая ячейка: так видно, что данных нет.

## Ключ

**Ключ** — поле (или набор полей), значение которого уникально для каждой записи.

В примере Фамилия — не ключ: могут быть два Иванова. Надёжнее составной ключ «Фамилия + Класс» или отдельное поле «Номер личного дела».

Ключ нужен, чтобы отличать одну запись от другой — как с индексом элемента массива.

## Работа с готовой базой

Три основные операции:

- **Поиск** — кто выше 170? Ответ: Сидоров (178).
- **Сортировка** — по росту по убыванию: Сидоров, Иванов, Петрова.
- **Фильтрация** — только 9А: Иванов, Петрова.

Это те же инструменты, что и в табличном процессоре, но над таблицей записей.

## Когда нужна одна таблица, а когда несколько

Одна таблица работает, пока у объекта однородные свойства. Если свойства относятся к разным сущностям — нужны несколько таблиц.

Пример: «Ученики» и «Оценки». Оценки — не свойство ученика, а отдельные записи со ссылкой на ученика. В одной таблице получится много пустых ячеек.

## Практическая работа

Задание КТП: создание однотабличной базы данных и поиск данных в готовой базе.

1. Создай таблицу «Ученики»: Фамилия, Имя, Класс, Рост, Средний балл.
2. Внеси 10–12 записей.
3. Найди: кто выше 170? Кто в 9А? У кого балл 5?
4. Отсортируй по среднему баллу по убыванию.
5. Отфильтруй: только 9Б.
6. Определи, какое поле может быть ключом и почему другое — нет.

## Ключевое (записать)

- Табличная модель: столбцы — поля, строки — записи.
- В столбце — один тип данных; в строке — один объект.
- Ключ — поле, уникальное для каждой записи.
- Поиск, сортировка, фильтрация — операции над базой.

## Частые ошибки

- Записывать в ячейку несколько значений («Иванов 170»): база перестаёт работать.
- Считать фамилию ключом: одинаковые фамилии бывают.
- Оставлять пустые ячейки вместо прочерков: не видно, где нет данных.
- Смешивать типы в одном столбце: сортировка и вычисления ломаются.

## Проверь себя

1. Что такое поле, запись, ключ?
2. Почему фамилия — ненадёжный ключ?
3. Назови три операции над табличной моделью.
