# Таблицы, связанные умом

**Реляционная БД** — набор связанных таблиц. Строка — **запись** (один объект), столбец — **поле** (свойство).

## Ключи и связи

- **Первичный ключ** — поле, уникально называющее запись (номер паспорта, id ученика). Двух одинаковых быть не может!
- **Внешний ключ** — ссылка на чужую таблицу (класс ученика → справочник классов). Так таблицы связываются без дублей.

Проектирование: сущности → таблицы; поля → типы; ключи → связи. Сначала на бумаге!

## Запросы: выборка, сортировка, фильтр

- **Запрос на выборку**: только нужные поля и строки (всех, у кого балл > 80).
- **Сортировка**: упорядочить (по фамилии, по баллу вниз).
- **Фильтрация**: временно спрятать лишнее (только свой район).

## Ключевое (записать)

- Запись — строка, поле — столбец. Первичный ключ уникален.
- Связи — через внешние ключи, без копипасты данных.
- Запрос: выбрать → отсортировать → отфильтровать.

## Частые ошибки

- Ключ с повторами (два id 5 — база врёт!).
- Копировать справочники в каждую строку вместо связи.
- Сортировать один столбец (строки разъедутся — как в таблицах!).

## Проверь себя

1. Что годится в первичные ключи: фамилия? номер паспорта? рост?
2. Как связать «Ученики» и «Классы» без дублей?
3. Чем выборка отличается от фильтра?
