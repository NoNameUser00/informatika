# Как компьютер хранит числа

## Целые числа

Целое число занимает фиксированное число бит: 8, 16, 32, 64. Например, `int` в Python — 32 бита, значит диапазон примерно от −2·10⁹ до 2·10⁹.

Как кодируют знак:

- **Знак и модуль** — старший бит отдан знаку, остальные — модулю. Минус один — это две единицы (`1000…0` и `1111…1`).
- **Дополнительный код** — отрицательное число получается инвертированием модуля и добавлением единицы. Этот способ эффективнее для вычислений, поэтому его используют на практике.

Разрядность определяет и диапазон, и точность: 64 бита — больше, чем 32.

## Вещественные числа

Вещественное число хранится как **знак + мантисса + порядок** — по сути, двоичная научная запись:

```
  1,0101 × 2⁵
  ↑     ↑
мантисса порядок
```

- **Мантисса** задаёт значащие цифры.
- **Порядок (экспонента)** — на сколько нужно сдвинуть двоичную точку.

## Почему 0,1 + 0,2 ≠ 0,3

Это не ошибка программы, а свойство двоичной записи дробей. Числа 0,1 и 0,2 в двоичной системе **бесконечные периодические**:

```
0,1₁₀ = 0,0001100001111011111…₂
0,2₁₀ = 0,00110000111101111…₂
```

Компьютер хранит конечное число разрядов, поэтому 0,1 и 0,2 округляются. Округлённые значения складываются не точно.

Отсюда правила программирования:

- сравнивать вещественные числа с учётом погрешности,
- не накапливать мелкие прибавления в цикле,
- для денег использовать целые числа (копейки) или decimal-типы.

## Точность

Чем больше разрядов отведено под мантиссу, тем точнее число. 32-битное вещественное даёт примерно 6–7 значащих цифр, 64-битное — около 15–16.

Отсюда странность: `0,1 + 0,2` может вывести `0,30000000000000004`, потому что двоичное представление не помещается в конечное число разрядов.

## Форматы

- **Одинарная точность** (float, 4 байта) — быстро, достаточно для графики и игр.
- **Двойная точность** (double, 8 байт) — стандарт для научных вычислений.
- **Десятичный формат** — хранит число в десятичной системе, «честное» 0,1; медленнее, применяется для денег.

## Ключевое (записать)

- Целые: фиксированная разрядность (8, 16, 32, 64 бит), знак и модуль или дополнительный код.
- Вещественные: знак + мантисса + порядок.
- 0,1 + 0,2 ≠ 0,3 из-за конечности разрядов двоичной дроби.
- Для денег — целые числа или десятичный формат.

## Частые ошибки

- Считать, что 0,1 + 0,2 ≠ 0,3 — баг: это свойство двоичной записи.
- Сравнивать вещественные числа прямым `==`: используют сравнение с погрешностью.
- Путать разрядность целого и число знаков после запятой.
- Считать, что double хранит бесконечно много цифр.
