# Архив одноразовых генераторов банков

Здесь лежат 22 скрипта, которыми банки заданий создавались в первый раз.

## Почему они не в `scripts/`

Каждый из них переписывает файлы `data/tasks/**/bank-*.yaml` целиком, от
первой строки до последней. Банки с тех пор изменились человеком: в каждом
`single_choice` проставлен проверенный ключ с якорем `answer_text`, варианты
перемешаны и переставлены по буквам, отвлекающие выровнены по длине. Повторный
запуск такого скрипта не «обновит банк», а молча вернёт его к состоянию на день
создания — вместе со всеми проверками.

Опасность тут не в самом запуске, а в виде: команда выглядит безобидно, ничего
не спрашивает и не предупреждает. Поэтому генераторы убраны из рабочего
каталога. Ни один из них не вызывается из `npm run rebuild`, `npm test`, CI и
Deploy — перенос ничего не ломает.

## Что с ними делать

Ничего. Это история создания банков, а не инструмент. Нужен контекст, почему
задание сформулировано именно так, — проще открыть скрипт, чем гадать.

Вернуть скрипт в рабочий каталог стоит только вместе с защитой: он должен
отказываться работать, если банк меняли руками. Сейчас такой защиты нет, и
`scripts/legacy-generators.test.mjs` следит, чтобы новые генераторы банков не
появились в `scripts/` — там разрешён только `make-numsys-bank.mjs`.

## Исключение, оставшееся в `scripts/`

`make-numsys-bank.mjs` — не одноразовый. Он подключён к `npm run bank:gen` и
делает `data/tasks/8/number-systems/bank-gen.yaml`: ответы там считает код, а не
человек, и каждая задача проходит проверку `check.mjs`. Переписывать его нечем.
